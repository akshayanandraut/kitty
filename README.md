# Kitty

Kitty is a women-only group planning and money-recording product. The public preview and Grasany sign-in are deployed at `https://kitty.grasany.com`. The group flows are still a **local development slice** using synthetic people. There is no open Kitty member registration, real KYC, payment collection, or real money transfer.

Run `npm test`, then `npm run dev` and open `http://127.0.0.1:4173`. Local demo identities are accepted only when `KITTY_LOCAL_DEMO=1` and the server binds to loopback. Data persists in `data/kitty.json`; remove that file to reset sample data. This mode must never be enabled in a public deployment.

Production group access remains closed until central identity verification projection, an approved one-time payment contract, and a full authenticated journey are connected and tested. Kitty's dedicated Grasany PKCE client is deployed. On 2026-10-24, a real browser journey reached Kitty's central OAuth consent, returned to the canonical callback, established a session that survived reload, and cleared that session on logout. No age or women-only statements were submitted during that check, so profile save/reopen and group access remain unverified. Kitty has its own Supabase project and certificate-verified database connection on Vercel. Profile editing, private photo upload and review, group creation, application, electorate review, voting, logged rejection override, meetup planning and RSVPs, member-approved shared expenses, and consent-based host handover have server-side routes guarded by a real product session. The signed-in workspace calls these routes when identity and access are active; they are not yet a verified live member journey. Identity verification does not establish gender or safety. Women-only eligibility is self-attested and subject to moderation.

`npm run build` prepares the public Vercel preview in `dist/`. The hosted `/api/status` function checks dedicated database connectivity and reports SSO configured while declaring identity verification, group operations and checkout closed. `/api/public` supports city/area/name and optional nearby search over host-approved coarse public area pins; it never returns a venue or member coordinates. Public text search includes open meetup previews and discoverable circles; nearby search includes circles with a host-approved broad area pin. The public page does not accept real member data. Git auto-deploy is disabled so publication uses a reviewed, explicit deployment to Kitty's single Vercel project. Motion is decorative and respects `prefers-reduced-motion`; the cat's eyes respond only to local pointer position when motion is allowed.

Bishi has a private, group-scoped ledger and committed-seed draw implementation for fixed consenting participants, outside contributions, peer confirmations and recipient-confirmed payouts. It is **disabled in Production** (`KITTY_BISHI_ENABLED` is absent). Even after an operator enables it, a group-specific legal authorization with validity through the last round is required before a proposal or draw. Kitty does not hold or transfer pooled money. Whether a particular plan is a regulated chit or qualifies for an exception needs qualified legal review; the absence of platform custody alone is not treated as clearance.

## Current local flows

- Public discovery shows only opt-in public group summaries and available slots.
- Hosts can open a future meetup to newcomers. Public previews show city, time, theme, typical monthly cost and capacity, while venue and reservation details stay among members. An optional random suggestion requires a click and can be declined before any join request.
- Members can create groups, request or accept invitations, vote on applications, join a waitlist, and belong to multiple groups. An applicant explicitly shares a profile snapshot with verified members of that group. At least half the frozen eligible electorate must vote yes; rejection starts a group-specific three-month cooldown, with a logged verified-admin override.
- Group members can schedule events and RSVP, record member-defined contribution obligations and payments, propose shared expenses with exact integer-paise splits for members or event attendees, and record settlements. Each included person confirms an expense share before it is agreed. These are records only.
- Hosts can rotate and set rules. Members can report or block users. Contact details are shared only by explicit consent within an authorized group. In the production workspace, an active member can leave her circle; open Bishi participation blocks exit. A sole host can invite a current member to become a co-host, who must accept before the original host can leave. Member removal and report resolution are not yet implemented.
- A hosting cycle records the assigned event host, completed hosting and explicit exceptions. Cancelled meetings never count as hosted. The next cycle starts only after all current participants have hosted or have an exception. Exception approval is currently a single group-host action; a multi-member approval rule is pending.
- Members can export their own record snapshot or request local account deletion.

The local API keeps a serialized transaction queue and writes snapshots atomically. It is a development adapter, not a production database. The Git migrations in `supabase/migrations/` were applied to Kitty's dedicated Supabase project on 2026-10-20. The private voting tables, photo table and photo bucket were verified over certificate-validated TLS. Photos are currently stored in a private database table, re-encoded as metadata-free WebP; the bucket has no browser access policy and is unused. The Vercel database credential is configured as a Production secret. Production code still needs authenticated Grasany SSO, an actual WhatsApp verification provider, central identity status projection, group moderation and removal policy, approved payment contract, protected heartbeat key, and real user journey verification.
